Session-Start 脚本

hooks/session-start（简化版）

#!/usr/bin/env bash set -euo pipefail ROOT="$(plugin_root)" skill="$ROOT/skills/using- superpowers/SKILL.md" content="$(cat "$skill")" printf '{"hookSpecificOutput": { "hookEventName": "SessionStart", "additionalContext": "%s" }}' \ "$(escape_json "$content")"

执行步骤

  • 定位已安装的 plugin
  • 读取 bootstrap SKILL.md
  • 将 Markdown 转义为 JSON
  • 作为 additionalContext 返回
  • Claude Code 将其加入 context

TOKEN COMPRESSION

为什么要压缩
Agent 的 tokens？

Context 被填满

日志、diff 和 tool 输出挤占了工作空间

每次交互都有成本

Tokens 需要付费和等待，双向都有

Compaction 丢失细节

晚期裁剪 context 会丢掉重要的信息

压缩前 — 786 行测试输出

$ npm test FAIL src/api/client.test.ts ● client › retries on 5xx connect ETIMEDOUT 10.0.3.8:443 at client.ts:88 ... 776 more lines ... 3 failed, 214 passed
↓

压缩后 — 模型看到的内容

3 tests fail: ETIMEDOUT at client.ts:88
双向压缩 — 并保留原始内容以供检索

压缩 tokens

🎯 五大不确定性来源

Live with Uncertainty

Natural language → 语义不确定性 semantic uncertainty
Retrieval / context → 检索漂移 retrieval drift（索引更新、分块、上下文截断）
Model generation → 概率变异性 probabilistic variability（1. 采样 2. 软硬件非确定性）
Agent/tool loop → 轨迹/环境非确定性（工具失败、环境变化）
Generated program → 生成后通常确定性（除非运行时调用模型或工具）
✅ 最佳实践

Best Practices for Programming / Software 3.0

1 · DEFINE

  • 提前声明假设：让模型在执行前确认任何模糊之处
  • 指定结果，而非 prompt：给出需求、不变量、约束和验收测试

2 · CONTROL

  • 分离提案与执行：Agent 提出计划，验证后再提交
  • 显式管理上下文：拥有记忆、来源和检索；过期陈旧信息

3 · VERIFY & GOVERN

  • 收紧生成-验证循环：廉价频繁检查优于最后一次性昂贵审查
  • 深一层度量：创建测试、衡量多指标、合成工作负载
💡 核心原则

Do not expect the agent to be deterministic;
make the surrounding system dependable.

将自主性与风险匹配：自主性越高，不确定性和风险越大
